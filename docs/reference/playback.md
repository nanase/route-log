# 動画の再生

WebView2 での直接再生を使います。作業機では実ファイルがそのまま再生でき、シークも 0.5 秒以内に終わりました。H.264 への変換は、直接再生できない環境のための代替として残します。

## 検証結果

17 GB のファイル 2 本を、Tauri 2.12 と WebView2 154 で測りました。

| 項目 | 結果 |
| --- | --- |
| 読み込み | 再生できる状態まで約 1.2 秒 |
| 等速 | 5 秒で 5.00 秒進み、フレーム落ちなし |
| 2 倍速 | 5 秒で 10.00 秒進む。フレーム落ちは 300 枚中 0〜11 枚 |
| 4 倍速 | 5 秒で 20.0 秒進む。フレームは半分落ちる |
| シーク（停止中） | 230〜490 ms で次のフレームが出る。末尾付近も同じ |
| シーク（再生中） | 250〜390 ms |
| 逆再生 | できない。負の再生速度は `NotSupportedError` になる |

- 計測は、アプリの動作確認の仕組みで行った。`ROUTELOG_CHECK_FILE` に動画を渡して起動すると、読み込み・再生・シークを測る（[動作確認](../guides/development.md#動作確認)）
- 画が出ていることは、取り出したフレームが真っ黒でないことで確かめた
- 逆再生（J キー）は、短い間隔のシークを繰り返して代用する。1 回のシークが 0.3 秒ほどなので、コマ送りに近い動きになる

## 方式 1: 直接再生

採用した方式です。

- Tauri のアセットプロトコル（`convertFileSrc`）でローカルファイルを `<video>` に渡す
- Windows に「HEVC ビデオ拡張機能」が入っており、GPU のハードウェアデコードが使える必要がある
- 設定の scope は空にし、Rust 側で名指ししたファイルだけを読めるようにする
- Tauri 2.12 のアセットプロトコルは Range 要求に対応するが、1 応答は約 1 MB までである
  - 約 32 Mbps の動画では、等速再生で毎秒 4 回ほどの要求になる
  - 作業機では 2 倍速まで問題にならなかった。127.0.0.1 のサーバは要らない

## 方式 2: プロキシ再生

直接再生できない環境のための代替です。まだ作っていません。

- Rust 側から ffmpeg（サイドカー）を呼び、360p 程度の H.264 に変換する
- GPU エンコード（`h264_nvenc` / `h264_qsv` / `h264_amf`）を検出して使う
- キーフレーム間隔を短く（例：1 秒）してシークを速くする
- 変換ファイルは一時フォルダに置き、走行の編集完了後に削除できるようにする

## 共通

- 1 つの `<video>` 要素でファイルを切り替え、仮想タイムライン上は連続再生に見せる
- ファイル境界をまたぐシークでは、次のファイルを事前に読み込んでおく
  - 事前の読み込みは未実装。いまは終わりに着いてから切り替え、約 0.8 秒止まる
